# CIS-S3-001: S3 bucket allows public access

Severity: CRITICAL. Category: DATA_PROTECTION.

## What it means
The bucket does not have all four S3 Public Access Block settings enabled (BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets). A public ACL or bucket policy can then expose objects to anyone on the internet.

## Attack scenario
An attacker lists or downloads objects without credentials, finds backups, logs or customer data, and uses leaked secrets found in them to move further into the account. Public buckets are scanned continuously by automated tools.

## Evidence to check
- `aws s3api get-public-access-block --bucket <name>`
- Bucket policy statements with `"Principal": "*"`
- Bucket and object ACL grants to `AllUsers` or `AuthenticatedUsers`
- CloudTrail S3 data events and access logs for requests from unknown IPs

## Related controls
CIS AWS Foundations 2.1.4, account-level S3 Block Public Access, IAM Access Analyzer for S3, S3 access logging.

## Remediation
Enable all four Public Access Block settings on the bucket and at account level. Remove public ACLs and wildcard-principal policy statements. Serve public content through CloudFront with origin access control instead. Review access logs for past exposure.
